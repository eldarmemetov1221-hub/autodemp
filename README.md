# AutoDemp — плагин автодемпинга для FunPayCardinal

Плагин автоматического демпинга цен для [FunPayCardinal (FPC)](https://github.com/sidor0912/FunPayCardinal).

Держит цену вашего лота **на шаг ниже** минимальной подходящей цены конкурента,
строго соблюдая **нижнюю границу (MIN PRICE)** и **защиту от ценовой войны**
(ограничение числа изменений цены в минуту). Управляется прямо из Telegram-бота
Cardinal.

---

## Возможности

| # | Возможность |
|---|-------------|
| ✅ | Демпинг: цена = `мин. цена конкурента − шаг`, но не ниже `MIN PRICE` |
| ✅ | Диапазон учёта конкурентов `[мин. цена, макс. цена]` |
| ✅ | **Защита от ценовой войны** — лимит изменений цены в минуту (напр. 10/мин) |
| ✅ | **Игнор-список продавцов** — их лоты не учитываются |
| ✅ | Автоматическое **исключение собственных лотов** (по `account.id`) |
| ✅ | Авто-повышение цены, если конкурент поднял свою (не только снижение) |
| ✅ | Стратегия «когда конкурентов нет»: не менять (по умолч.) / макс. цена / заданная цена |
| ✅ | Дробный шаг и дробный интервал (0.5 с и т.д.); несколько лотов независимо |
| ✅ | Кэш и дедупликация запросов; авто-ограничение интервала до безопасного |
| ✅ | Режим цены: **для продавца** или **для покупателя** (точная конвертация по комиссии FunPay) |
| ✅ | Понятные **логи** работы (найдено конкурентов, новая цена, ошибки) |
| ✅ | **Интерфейс настроек** внутри Telegram-бота Cardinal (карточка на лот) |
| ✅ | **Надёжность**: ретраи сетевых/FunPay-ошибок, защита от гонки потоков |
| ✅ | **Сохранение настроек** между перезапусками Cardinal |

## Установка

1. Скопируйте файл `plugins/autodemp.py` в папку **`plugins/`** вашего
   FunPayCardinal:

   ```
   FunPayCardinal/
   └── plugins/
       └── autodemp.py      ← сюда
   ```

2. Перезапустите Cardinal (или используйте загрузку плагина через Telegram:
   *Плагины → Загрузить плагин*).

3. Убедитесь, что плагин активен: в Telegram-боте откройте
   **⚙️ → Плагины → AutoDemp** — статус должен быть 🟢.

Дополнительные зависимости **не требуются** — плагин использует только то, что
уже входит в FunPayCardinal (`FunPayAPI`, `pyTelegramBotAPI`, `requests`,
стандартная библиотека Python 3.10+).

## Настройка

Всё управление — из Telegram-бота Cardinal:

**⚙️ → Плагины → AutoDemp → Настройки**

### Режим цены (важно)

Кнопка **💱 Цены: для продавца / для покупателя** на главном экране.

На FunPay две цены: **для продавца** — её вы вводите в поле лота (`get_lot_fields`
возвращает именно её), и **для покупателя** — с комиссией FunPay; **именно она
показывается в списке/таблице лотов** (`get_subcategory_public_lots` отдаёт
покупательскую цену). Это разные величины, и плагин это учитывает: он всегда
сравнивает конкурентов в цене покупателя, а при сохранении переводит результат в
цену продавца по **реальному коэффициенту комиссии** FunPay (`CalcResult`).

- **Для покупателя** — вы задаёте MIN/MAX/шаг **теми же числами, что видите в
  таблице FunPay** (цены покупателя). Нагляднее всего для сравнения с конкурентами.
- **Для продавца** (по умолчанию) — вы задаёте MIN/MAX/шаг в ценах продавца (как
  в поле лота). Плагин сам переведёт границы в покупательские для сравнения.

В логах видно обе цены: `177.68 ₽ (покупатель) → 161.56 ₽ продавцу`. Демпинг в
обоих режимах одинаков — режим влияет лишь на то, в каких числах вы вводите и
видите цены.

### Главный экран
- **➕ Добавить лот** — введите `Lot ID` (число или ссылку на лот FunPay).
- **🛡 Лимит изм./мин** — максимум изменений цены в минуту (защита от
  зацикливания при войне цен). По умолчанию `10`.
- **🚫 Игнор-список продавцов** — добавьте `ID продавцов`, чьи лоты не нужно
  учитывать. Свои лоты исключаются автоматически.

### Карточка лота
```
┌─ Автодэмпинг ─
│ Lot ID: 123456789
│ Статус: 🟢 Работает
│
│ Минимальная цена: 700.00 ₽
│ Максимальная цена: 800.00 ₽
│ Шаг: 0.01 ₽
│ Интервал: 1 сек
│
│ Текущая цена: 719.99 ₽
│ Конкурентов: 7
│ Подходящих: 4
│ Минимум конкурентов: 720.00 ₽
└─
```
- **Мин / Макс** — границы диапазона. Конкуренты вне диапазона игнорируются,
  цена никогда не опустится ниже **Мин**.
- **Шаг** — на сколько встать ниже конкурента (например `0.01`, `0.5`, `1`, `10`;
  поддерживаются дробные значения).
- **Интервал** — период проверки в секундах (поддерживает дробные, напр. `0.5`).
  Если значение меньше безопасного минимума FunPay (`MIN_SAFE_INTERVAL`, по
  умолчанию 2 с), плагин автоматически использует безопасный минимум, чтобы не
  нарушать ограничения запросов.
- **Без конкурентов** — стратегия, когда подходящих конкурентов нет:
  `не менять` (по умолчанию) / `макс. цена` / `заданная цена` (появляется поле
  для ввода своей цены).

#### Фильтры конкурентов

`get_subcategory_public_lots` возвращает **всю подкатегорию** (все способы
доставки, онлайн и офлайн продавцов, разные номиналы). Чтобы демпить именно
«тех» конкурентов, в карточке лота есть фильтры:

- **Доставка** — `все` / `по ID` / `по коду` (определяется по тексту лота).
- **Онлайн** — учитывать только онлайн-продавцов (как галочка «только продавцы
  онлайн» на FunPay).
- **Мин. отзывов** — игнорировать продавцов, у кого отзывов меньше указанного
  (например `1000`).
- **Фильтр текста** — учитывать только лоты, в описании которых есть указанный
  текст (например `120 UC`) — удобно, чтобы отсечь другие номиналы.

В карточке также показывается **Категория** (ID подкатегории FunPay, например
`1013`), в которой идёт демпинг, — чтобы вы видели, что он работает в нужном
разделе.

#### ⚡ Агрессивный режим (всегда 1-й)

Против чужого бота с задержкой обновления таблицы FunPay «всегда быть первым»
пошаговым подрезом не выйдет (вы читаете уже устаревшие цены). Гарантия только
одна: **быть готовым дойти до своей MIN и иметь MIN ниже, чем у конкурента.**

Агрессивный режим: как только рядом есть подходящий конкурент — плагин **сразу
ставит вашу MIN**, минуя пошаговую гонку и лаг. Вы мгновенно первый (если ваша
MIN ниже цены конкурента). Когда конкурентов в диапазоне нет — работает выбранная
стратегия «без конкурентов» (напр. макс. цена).

⚠️ Плата за это — вы продаёте по MIN, когда есть конкуренты (жертвуете прибылью).
Если конкурент опустится **ниже вашей MIN**, обойти его нельзя — нужен MIN ниже.
Обычный режим (подрез по шагу + низкий интервал) выгоднее по цене, агрессивный —
надёжнее по позиции.
- **▶️ Запустить / ⏹ Остановить** — включение демпинга по лоту.

Настройки сохраняются в `storage/plugins/autodemp.json` и восстанавливаются
после перезапуска Cardinal (лоты со статусом «Работает» запускаются
автоматически).

## Алгоритм

Для каждого включённого лота в отдельном потоке (интервал настраивается):

```
current_price = account.get_lot_fields(lot_id).price
competitors   = account.get_subcategory_public_lots(subcat.type, subcat.id)

competitors = исключить свои лоты (seller.id == account.id)
competitors = исключить игнорируемых продавцов
valid       = [c for c in competitors if min_price <= c.price <= max_price]

if valid:
    target = min(c.price for c in valid) - step
    if target < min_price:            # защита от бесконечного демпинга
        target = min_price
else:
    target = стратегия «без конкурентов»

if target != current_price and лимит изменений/мин не превышен:
    account.save_lot(lot_fields с новой ценой)

wait(interval)
```

## Используемые методы Cardinal / FunPayAPI

| Метод / атрибут | Назначение |
|-----------------|------------|
| `cardinal.account` (`FunPayAPI.Account`) | доступ к FunPay |
| `account.id` | ID своего аккаунта (исключение собственных лотов) |
| `account.get_lot_fields(lot_id)` | текущая цена (`LotFields.price`), подкатегория, поля лота |
| `account.get_subcategory_public_lots(type, id)` | список лотов конкурентов (`LotShortcut.price`, `.seller.id`) |
| `account.save_lot(lot_fields)` | сохранение новой цены (цены продавца) |
| `account.calc(...)` / `LotFields.calc_result` (`CalcResult.commission_coefficient`) | коэффициент комиссии для режима «цена для покупателя» |
| `cardinal.telegram` (`TGBot`) | интерфейс настроек |
| `tg.cbq_handler / msg_handler` | обработчики кнопок и ввода |
| `tg.set_state / get_state / check_state / clear_state` | пошаговый ввод значений |
| `CBT.PLUGIN_SETTINGS` | привязка кнопки «Настройки» плагина |
| `cardinal.plugins[UUID].enabled` | уважение ручного отключения плагина |

Точки входа плагина: `BIND_TO_PRE_INIT` (регистрация интерфейса),
`BIND_TO_POST_INIT` (загрузка конфига и запуск воркеров),
`BIND_TO_DELETE` (корректная остановка).

## Надёжность и обработка ошибок

- **Сетевые ошибки / ошибки FunPay** — до 3 повторов с экспоненциальной
  задержкой (2 → 4 → 8 сек). Повторы прерываются при остановке.
- **Восстановление после сбоя** — цикл лота не падает при исключении: ошибка
  логируется, поток ждёт интервал и продолжает работу после восстановления
  соединения.
- **Защита от гонки потоков** — на каждый `Lot ID` отдельный поток и
  неблокирующий `Lock`: один и тот же лот никогда не изменяется двумя циклами
  одновременно.
- **Защита от ценовой войны** — глобальный лимит изменений цены в минуту.
- **Корректная остановка** — через `threading.Event`; при удалении плагина
  (`BIND_TO_DELETE`) все воркеры останавливаются. Потоки — `daemon`, не мешают
  завершению Cardinal.
- **Сохранение настроек** — атомарная запись JSON (`.tmp` + `os.replace`).

## Скорость (п.9 ТЗ)

- Запрос на изменение цены **не отправляется**, если рассчитанная цена совпадает
  с текущей (сравнение с допуском).
- Список конкурентов **кэшируется** (`COMP_CACHE_TTL`) и **дедуплицируется**: если
  несколько лотов относятся к одной подкатегории, публичные лоты запрашиваются
  один раз, остальные потоки берут результат из кэша. Одинаковые одновременные
  запросы не выполняются повторно.
- Интервал проверки настраивается (в т.ч. дробный) и автоматически ограничивается
  безопасным минимумом, чтобы не превышать лимиты FunPay.
- За один цикл — минимум обращений: поля лота и список конкурентов.
